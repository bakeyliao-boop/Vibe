# ADR-0008：为随便浏览补齐稳定查找路径

- 决策状态：已接受（本轮 Mock 的同页查找与查看全部范围）
- 实施状态：已上线（预置样例范围；69edcf0）
- 验证状态：Chrome 浏览器检查已通过；真实 iPhone Safari 与真实用户找回任务未验证
- 建档 / 讨论日期：2026-09-12
- 类型：产品 / 交互
- 路线关联：[R1、R3、R5](../../ROADMAP.md)
- 关联：[ADR-0006](0006-ambient-memory-shuffle.md)、[ADR-0007](0007-relaxed-motion-timing.md)

## 问题与依据

无明确目标时，慢慢浮现的封面有助于浏览。急着找“杭州夜市”时，等待下一张封面不符合任务。提案时的画布同屏最多 7 张且没有查看全部；开启减少动态时，更多条目缺少直接访问方式。

初次建档时，用户只要求记录建议，尚未授权实现。随后用户要求基于当前 Mock 调整，并再次明确“继续推进刚才 mock 的调整”。本轮据此接受和实施下方记录的同页查找范围；真实导入、账户 / 同步及语义检索不在该授权的实现范围内。

## 初次提案的候选与建议

- 只使用自动换片和分组：界面简洁，但无法保证及时、完整找到内容。
- 全面改为列表：查找稳定，可能丢失已经确认的轻松浏览感。
- **建议：保留动态浏览，增加随手可用的搜索与“查看全部”。** 主动检索或浏览全部时静止展示，不要求用户等到某条随机出现。

初次提案尚未确定具体控件位置、是否原位切换、查询结果布局；该历史保留，当前采用方式见下方“本轮接受与实施”。无需先规定必须接 LLM；先用已有字段核对能找到什么。

## 预期收益与取舍

- 完整性：所有已保存内容都可通过手动路径访问，包括减少动态模式。
- 可理解性：保留当前地点、类型、来源等线索，结果支持明确原文入口。
- 需要兼顾界面密度，不能用大量筛选控件占满手机首屏。
- 标题没有“萧山”、记录中也没有地点时，不能仅凭查询词补出一个确定地点。

## 如何验证

先用当前素材检查全部可达，再用 R2 保存的真实分享开展找回任务。记录目标内容、用户剩余线索、是否找到、耗时和命中依据；与原来的群聊 / 平台收藏方法比较。找不到的也保留为失败样例。

## 未决问题

关键词和组合筛选是否足以支持真实用户的剩余印象？何时需要语义搜索？真实资源有多个地点或类型时怎样展现？本轮已确定当前样例范围内的返回状态，真实收藏持久化与跨设备恢复仍待后续决策。

## 当前 Mock 的优先级判断（2026-09-12 追加）

用户追问“这个 Mock 现在最需要解决的问题”。当时建议优先补齐 **从一点线索主动找到并打开某条已有内容** 的路径；该次讨论保持提案状态，没有据此开始开发。

当时证据：某分享人分组有 8 条样例、地点线索组有 9 条，`renderDeck()` 只把前 7 条设为可操作，其他项隐藏且不可点击；没有搜索或全部展开入口。用户只记得分享人时，该分组未显示的内容需要等待轮换，或尝试其他视角。已知某条明确地点且该组内容很少时，原有分类仍能帮助找到，不能笼统断言所有资源都找不到。

下一版建议收敛为一个连续体验：

1. 浏览时保留相册式浮现，在当前界面提供明确的查找与全部展开入口。
2. 主动查找时让封面停止自动轮换，以已有字段缩小范围，保留标题与命中线索帮助确认。
3. 点中目标后沿用原文入口；返回后能继续浏览，不丢查询上下文。

首个任务可以使用现有真实样例：“记得有人发过金华潜水内容，找到并打开它”；再验证超过 7 条分组中当前未显示内容能否被主动访问。萧山夜市是需求背景，当前素材中没有该条原分享，不能伪造一个搜索命中结果。

把 R1 作为 Mock 的下一步，是为了先证明找回交互是否清楚；R2 的真实导入仍是让正式产品持续使用的必要条件，不能从演示里已有样例推断保存问题已经解决。评价依据是无需讲解能否找到正确资源、是否需要等待、以及原文入口是否匹配，不用页面停留时长代替任务完成。

## 本轮接受与实施（2026-09-12 追加）

确认依据：用户在上述优先级讨论后提出“看看基于当前的 mock 该怎么调整”，中断后明确要求“继续推进刚才 mock 的调整”。本轮只补齐预置样例的找回路径，保留动态相册作为默认浏览方式。

### 同页双入口与范围

- 顶部“找一条”首次进入时展示全部 13 条，适合不知道原分组的查找。
- 当前组头“查看全部”进入该组的稳定封面网格，直接访问组内所有内容，包括 8 / 9 条的分组。该入口清空旧查询、采用用户刚选的分组，不让上次查找范围覆盖本次明确动作。
- 查找中保留地点 / 类型 / 分享人三视角。切换视角更换筛选项并重置到“全部”，保留查询文字；选中结果仍命中时继续保留，否则清除选中和旧原文入口。
- 网格原位替换动态画布。查找与查看全部期间停止自动换片、周边浮现和延后的原文栏更新；用户自主滚动全部内容。

### 已有字段检索与证据

- 仅检索样例已有的标题、简称、原作者、已记录分享人 / 日期、地点 / 地点线索、类型、平台及 URL。未知字段不补造成已知事实。
- 先匹配输入的完整词；连续中文词在没有已有字段直接包含时，使用浏览器 `Intl.Segmenter` 分词。多个词采用 AND：每个词都必须在该资源的某个已有字段中出现，可以跨字段命中。没有该分词能力时保留原词匹配。
- 结果标题高亮实际出现的搜索文字，另列“标题含…”或“匹配：地点、作者”等字段依据。此实现不是 LLM、语义搜索、纠错、自动导入，也不保证任意自然语言都能找到。
- 没有结果时明确显示空状态，允许清空关键词或扩大到全部内容；不保留上一个结果的原文按钮，防止误开无关内容。

### 选择、返回与状态

- 点击结果明确选中，原文栏只展示该资源的标题、出处、命中依据和实际链接；原文是否可达仍由外部平台决定。
- 返回相册时，已选资源进入当前视角的对应分组并保持选中；没有选中结果时恢复进入查找前的相册状态。
- 再次从“找一条”进入，恢复上一次查找的视角、查询、范围、选中结果及结果滚动位置。以上均为当前页面会话内状态，不承诺刷新后或跨设备保存。

### 当前检查与边界

实施证据位于 `index.html` 的 `openFinder()`、`renderFindResults()`、`getSearchResults()`、`closeFinder()` 和原文栏状态逻辑。2026-09-12 的隔离 Chrome 浏览器检查已通过，当前随 [`69edcf0`](https://github.com/bakeyliao-boop/Vibe/commit/69edcf0) 上线；发布一致性证据见下方。
