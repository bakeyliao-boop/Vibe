# ADR-0018：从小红书 / 抖音发起分享，Vibe 负责接收

- 决策状态：已接受（用户明确纠正入口；流程细节为本轮 Mock 实施选择）
- 实施状态：已上线（74ffe1b，本机 Mock）；真实 iPhone 分享扩展与平台解析未实现
- 验证状态：Chrome 本机 14 组检查、公开页冒烟及线上三文件一致性核对通过；待用户验收，未在小红书 / 抖音真机验证
- 建档日期：2026-09-12
- 讨论 / 决策日期：2026-09-12
- 类型：产品 / 核心交互 / 数据输入
- 路线项：[R2、施工前 Mock M1、M2、M6](../../ROADMAP.md)
- 关联 / 替代：部分替代 [ADR-0009](0009-low-friction-capture.md)、[ADR-0014](0014-prebuild-mock-completeness.md)、[ADR-0015](0015-local-mock-data-and-capture.md) 的“到 Vibe 粘贴并预览确认”入口；保留轻量保存、缺失字段容错、本机事务、去重与失败处理。与 [ADR-0017](0017-platform-parsing-evaluation.md) 分别负责分享入口和元数据解析验证；角色规则仍按 ADR-0016。

## 具体问题

用户在小红书看到金华潜水内容时，动作应从那条内容的分享入口开始。上一版要求复制后切到 Vibe、粘贴并确认，增加了产品切换和录入步骤，也没有演示用户希望的使用起点。

用户明确反馈：“希望用户不要把链接粘贴到 Vibe，而是直接在小红书或者抖音发起。”本次把原平台分享作为主要保存路径，并用可辨认的前端示意检验承接过程。

## 依据

- 用户明确要求从小红书 / 抖音发起，纠正的是入口设计，不意味着已经完成原生接入。
- 前一版 `8163f7d` 的本机粘贴流程已发布但未获用户验收；本轮保留已验收的 `69edcf0` 查找交互及 ADR-0007 的松弛基调。
- 主对话于 2026-09-12 核对 Apple [Share 扩展说明](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html)：分享扩展接收宿主传入的文字 / 附件，界面应适合简短操作，完成后可结束请求并返回宿主。
- Apple [扩展常见场景说明](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionScenarios.html) 表明扩展是否可用与宿主提供的附件类型及激活规则有关。这不能证明小红书 / 抖音的任意自定义菜单都会出现 Vibe，也不能证明实际能取得标题和封面。
- 本项目为 GitHub Pages 前端 Mock。浏览器示意不能向 iPhone 系统安装分享扩展；两个原平台的入口名称、位置、可达性与实际传入字段仍待真机检查。

## 候选与当前选择

- 继续在 Vibe 粘贴：已有实现，但不符合用户明确要求，退出本轮主路径。
- 分享后打开 Vibe 并填写完整表单：起点改变，但仍让用户承担整理工作，不作为必经流程。
- **当前选择：原平台发起 → 选择 Vibe → 自动保留收到的信息 → 在简短承接页给出结果 → 继续浏览来源。** 默认保存到当前演示相册，提供显式切换相册；不要求粘贴、填写标题或再次必经确认。去 Vibe 查看是可选动作。
- Vibe 内的新增入口改为“如何收下”说明。页面外“体验场景”提供“从小红书分享 / 从抖音分享”的可重复演示，原平台页面与共享目标列表均明确标为概念示意。
- 确认依据：入口方向由用户明确要求；自动承接、返回来源优先及沿用当前演示相册是本轮执行中的具体选择，待用户验收，不视为生产空间模型已经确定。

## 结果与取舍

1. 不依赖用户进入 Vibe 粘贴。在承接页直接保存收到的文字与地址；资料不全不要求当场补齐，后续仍可在内容背面更正。
2. 先实际写入本机，成功后才反馈并更新各视图。模拟或真实存储失败均保留输入、说明尚未保存并允许重试；不能把收到信息等同于保存成功。
3. 重复分享沿用保守去重，显示已经收下，并提供继续浏览来源与可选查看已有记录；不悄悄切换到另一相册以绕过去重。生产多次分享事件历史仍未决定。
4. 小红书演示复用公开预置样例 `seed8`，明确为预置资料、未联网解析。抖音演示使用明确的合成内容，不使用 `.local/` 中的三条真实研究样本。
5. 合成内容始终带 `isFlowDemo` / `demoSourceId` 标识；演示链接指向本站 `?demo=source-douyin`，相关入口统一称“查看分享演示”，不能称为原文。刷新、改错、复制或从查找进入后仍需保留这一边界。真实样例仍使用真实原文路径。
6. 接收成功与解析成功分开：分享入口先保证传来的资料被保住；标题、封面和配文的有效取得继续按 ADR-0017 评估。LLM 不补造没拿到的原封面或正文。
7. 本轮不安装原生扩展，不接账户、平台解析、云同步或服务端权限，不调用或购买第三方解析服务。两平台实际分享菜单和实际载荷只能通过后续真机测试确认。

## 如何验证 / 何时重看

- 从页面外选择一种来源演示，核对来源与模拟标识；选择 Vibe 后无需输入 / 再确认就到达保存结果，默认相册不暗中变化。
- 保存后核对相册、地点 / 类型 / 分享人、搜索与详情是同一条记录；重复分享数量不增加，返回来源和可选查看目标均正确。
- 用信息不全、模拟失败和实际本机写入失败分别检查输入留存、提示和重试；只读角色仍不得通过分享承接写入。
- 核对合成抖音记录在相册、结果、详情、回查及刷新后的所有打开入口只进入本站演示，真实原文入口不受影响。
- 在手机尺寸与减少动态环境检查关键按钮可达、弹层暂停与返回后的上下文；这些属于浏览器 Mock 检查，不代表 iPhone 真机通过。
- 真正施工前，用 iPhone 分别检查小红书图文 / 视频、抖音视频等目标分享形式：能否进入系统分享、能否选扩展、传入哪些字段、完成后能否回到原内容。随后单独检查解析对应性和失败结果；若原平台无法提供预期入口，再基于实测讨论替代路径。

## 未决问题

原平台真机入口和附件类型、分享扩展在不同应用版本中的可用性、真实账户默认相册与多空间选择、后台资料补全及失败通知、原生保存延迟与跨设备同步仍待确定。原平台 UI 示意不作为其真实交互规格。

## 本轮实现与检查（2026-09-12，发布前）

Vibe 顶部“如何收下”和空相册“了解如何分享”只展示指南，不含粘贴 / 标题输入框；指南可明确更换接收相册。页面外“体验场景”启动小红书或抖音的来源示意，选择 Vibe 后直接保存。成功 / 重复反馈留在来源演示，主动作继续浏览，去 Vibe 查看可选。默认 13 条示例中的已知小红书再次分享会先演示重复，并有场景提示说明；不会为了看见新增而暗中换库。

Chrome headless 完成 14 组检查，结果如下：

| 检查范围 | 已观察到的结果 |
| --- | --- |
| 指南、接收相册与默认重复 | 无粘贴 / 标题输入；换库须明确操作；默认示例保持 13 条、重复不换库、不新增 |
| 自动保存与可选查看 | 接收后本机写入并反馈；查看相册可选，真实预置样例外跳目标与所选原链接一致 |
| 维护与数据联动 | 新增后的标题更正、搜索、删除 / 撤销及刷新留存通过 |
| 资料不全与失败 | 资料不全保留收到的标题 / 地址，封面为空、地点未知；模拟失败可重试；实际 `Storage.setItem` 抛错时旧库不变，重试后写入成功 |
| 入口缺失与只读 | 无分享入口场景不保存；guest 预览角色不能通过承接页写入 |
| 邀请成员与弹层 | 经现有邀请流程加入后分享抖音，新记录 `createdBy` / `person` 为 `demo-friend`；成员可更正自己的记录，不能更正 `seed8`；弹层期间 `root.is-overlay-open` 为真 |
| 合成抖音来源边界 | 编辑和刷新后仍有永久演示标识；搜索结果角标和各打开入口统一显示分享演示；本站 `?demo=source-douyin` 重进后再次保存识别为重复 |
| 手机布局与动态 | 320×568 明色、375×812 暗色、393×852 明色、390×480 减少动态：弹层和底部按钮处于视口内，关键目标不少于 44px，无横向溢出；截图已目视 |

同行审查发现合成抖音搜索结果曾使用“原分享”措辞，已改为“查看分享演示”并复核。来源示意不证明原平台当前菜单或实际传入字段；真实原文只核对目标一致性，不声称平台作品当前可访问。本轮未做真实 iPhone 系统分享，未访问本机私人研究样本，未调用第三方供应商。本段为发布前检查记录：当时产品已本地提交 `74ffe1b`，线上核对尚未完成；后续发布结果见下节，用户验收仍待完成。
