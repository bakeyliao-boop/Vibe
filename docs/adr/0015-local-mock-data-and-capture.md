## 具体问题

体验者想从空相册收下“金华潜水”，又需要随时回看原来的 13 条示例。收下之后必须在分组、查找和内容背面看到同一条记录；如果浏览器没存成功，不能仍显示“已保存”。陌生链接也不能借用预置封面，造成已经联网识别的误解。

## 依据

- 用户已接受轻量保存，并明确要求在保留现有基调上补齐施工前前端 Mock。
- 当前项目在 GitHub Pages 运行，不具备真实平台解析服务、账户或云数据库。
- `lifecycle.js` 的 `extractShare`、`buildCapturedItem`、`commit`、`loadState` 和 `updateSelection` 实现本轮数据路径；`index.html` 提供替换记录、分组与查找接口。
- Chrome 检查覆盖从空相册新增、刷新留存、改错联动、重复不新增、删除 / 撤销、模拟失败重试，以及实际存储写入抛错时旧库与输入保持；损坏原字符串不被自动覆盖、可进入恢复流程，非 HTTP(S) 输入被拒绝。

## 候选与当前选择

- 单一示例库直接覆盖：实现少，但重置时难区分演示资料和体验者新增记录。
- 仅内存模拟：可以演示按钮，却无法验证刷新后继续使用与写入失败。
- **当前选择：默认示例库与独立的本机空相册分别保存，用同一套数据流程驱动所有视图。** 使用 `localStorage` 键 `vibe.mock.lifecycle.v1`，保存两个库及当前演示角色 / 邀请状态。
- 确认依据：本次“帮我改”的执行授权下，为完整且可重复的前端体验作出的必要选择。生产数据库、私人 / 共同空间模型尚未决定。

## 结果与取舍

1. 示例库初始包含 13 条，自己的相册初始为空。两库分别保留；确认恢复示例只重置示例库，保留自己的记录。切库不代表向其他成员发布内容。
2. 新状态先写入浏览器，成功后才替换内存和视图；写入失败不提前显示成功、不改变旧库，输入保留以便重试。损坏或不可读数据不会自动覆盖，先提示重读；重置需要确认。跨标签页变化阻止继续覆盖，要求显式重读。
3. 只从粘贴文本取得 HTTP(S) 链接与文字，标题允许手填。陌生链接的原作者、封面、地点、类型保持缺失；平台未知时显示网页 / 域名，不伪装成小红书。
4. 已知小红书内容标识可以匹配原有预置资料，预览和详情明确写“未联网解析”。本次收下时间与操作者按实际本机操作记录，不沿用旧样例时间冒充本次分享。
5. 同小红书内容标识或同完整 URL 才判为重复，回到已有记录；不因同域名、相似标题或同地点合并。短链未解析时可能保留为另一记录；尚未建立多次分享事件历史。
6. 新增、改错、移除 / 撤销统一重建当前库的相册、分组、搜索与关联数。出处保留与编辑后标题分开，撤销恢复原记录身份。复制被拒时提供可手动选中的原链接 / 标题。
7. 本机持久化只对同浏览器、同站点有效；清除浏览器数据会失去这些演示记录，不代表云端备份或跨设备同步。

## 如何验证 / 何时重看

从空库收下一条，再刷新并查找；更正地点后核对旧组移除、新组加入及相关数量；删除再撤销核对 ID 与原链接。将实际存储写入模拟为抛错，核对输入与旧库存续。确认恢复示例后，自有记录数量不变。复制不可用时仍能手动取回文字。

接入真实平台、云端或多设备编辑前，重开数据模型、持久化与冲突处理决策，不能直接把本轮角色 / 本机存储当生产实现。

## 未决问题

真实平台可取得字段、短链解析、跨平台内容身份、重复分享事件、云端数据迁移 / 备份、生产空间模型与多设备冲突处理仍待确定。
