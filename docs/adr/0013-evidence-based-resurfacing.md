# ADR-0013：让旧内容浮现带有真实的记忆线索

## 问题与依据

当前换片改变的是封面主位。看到潜水图片时，用户还可能需要“谁分享的、当时什么时候、还有什么相关内容”等线索，才能想起它与自己的关系。

上一轮建议让浮现内容附带真实日期和来源，未来优先展现较久没看过的内容。用户尚未确认具体排序和卡片信息方案。

## 候选与当前建议

- 保持纯随机：简单，但可能只产生视觉变化。
- 自动生成共同喜好或想去结论：原始分享不能证明这些判断。
- **建议：在不增加填写负担的前提下，浮现时带上已有的来源 / 时间线索，再验证是否需要基于长期未查看记录排序。**

“某成员在某日分享”“同一地点还有另外两条”只有对应字段和关联依据存在时才展示。导入时间不能写成原群聊分享时间；多个平台谈及同地点不能自动合并为同作品。

## 结果与取舍

这可能把随机播放变成有上下文的回顾，但需要实际事件数据。当前 `recentFocusedIds` 只规避本次会话最近主焦点，没有长期浏览记录，不能写“很久没看过”或“当年的共同喜好”。

显示多少来源信息、成员间是否共享查看记录、个人未看过和小组未看过如何区分，都需要讨论。不要为实现再发现而默认采集成员的所有浏览行为。

## 如何验证 / 未决问题

比较只看封面与带真实线索的回顾，询问用户是否认出当时的分享、是否打开原文、是否觉得文字干扰松弛感。若已有日期与来源已足够，不必先实现复杂排序。

未确定：长期记录是否必要、浮现优先级、重复分享的记录方式，以及个人查看信息的访问范围。
