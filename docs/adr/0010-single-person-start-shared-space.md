# ADR-0010：允许一个人先使用，再邀请朋友

- 决策状态：已接受（单人启动方向与本轮角色演示；真实访问细则待确定）

- 建档 / 讨论日期：2026-09-12

## 问题与依据

一个发起人希望把已经分享的内容整理起来，另外两位朋友未必愿意马上安装并建立空账户。如果三人必须同时开始，首次价值会依赖整个小组完成准备。

这是上一轮提出的启动成本假设，尚无真实小组试验。当前“分享人”仅为样例分类，不是已有多人系统。

## 候选与当前建议

- 三人全部注册后才能创建：步骤一致，但前期协作成本可能高。
- 纯个人工具：一人容易开始，但不验证当前共同使用方向。
- **建议：一人可保存并积累，朋友先方便查看，愿意贡献时再加入。** iPhone 保存体验与网页查看可以作为候选搭配。

是否免登录、具体邀请形式和产品内加入路径均未确定。网页便于查看不代表共同空间默认公开。

## 结果与取舍

- 邀请可展示已存在的内容，理由更具体。
- 必须区分原作者、导入者与原分享者，维护可靠贡献记录。
- 查看与编辑权限需要明确；撤销邀请后如何失效、转发链接能否被其他人查看，需进一步设计。
- 当前公开 Pages Mock 不满足真实私人空间的访问控制要求，不能直接作为多人隐私方案。

## 如何验证

观察发起人能否独立获得价值、朋友是否打开已有内容、是否返回查看或贡献。若长期只有发起人使用，应重新评估共享优先级，而不是把接受邀请人数当共同使用成立。

## 未决问题

个人与共同空间是否都需要？邀请及权限机制如何定义？未加入成员怎样查看？是否支持 Android 保存或只提供网页查看？成员退出后内容和来源如何处理？

## 方向确认（2026-09-12）

用户接受前述四点建议，包含“一人先开始使用，朋友随后查看或加入”。该方向已接受，账户 / 邀请 / 同步尚未实现；并未同时确定独立私人空间、多空间切换、免登录访问或具体成员权限。

施工前 Mock 建议演示一个人从空空间开始，再进入邀请、朋友查看 / 加入的过程，让用户看清内容可见范围和操作权限。角色切换演示不等于真实多人同步；具体补齐范围见 [ADR-0014](0014-prebuild-mock-completeness.md)。

## 本轮实现记录（2026-09-12，以下为发布前状态）

用户要求在原有基调上补齐前端 Mock。现可保留默认示例相册，另从自己的空相册开始，一个人收下第一条；随后在“一起留着”中生成演示邀请、预览朋友收到的说明、先只读查看或加入成为“小禾 · 演示”。双方均在当前浏览器操作，没有发送真实邀请、可外传的私人内容链接或跨设备同步。

本轮权限演示采用发起人维护全部、预览者只读、成员仅维护自己新增的内容，并以 `createdBy` 判断操作者归属，保留原样例的分享来源。生成邀请、加入、过期及重新生成都有明确状态。具体边界与未决的生产权限见 ADR-0016。示例与自己的两套数据仅用于重复体验，不能据此断言生产产品已确定私人空间和共同空间并行模型，详见 ADR-0015。

Chrome 已检查只读 / 成员界面和操作处理、邀请过期后不能加入及重新生成后可继续。真实用户身份、服务端权限与邀请外发仍未实现，亦无本轮用户验收。
