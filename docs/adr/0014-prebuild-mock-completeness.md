## 具体问题与依据

用户已接受四个方向：随便浏览与主动查找并存、轻量保存、一人先用再邀请朋友、附带真实线索的再发现；随后询问施工前的完整前端 Mock 还需调整什么。

当前 `69edcf0` 已获用户验收，但它从 13 条预置内容开始，能够浏览、字段查找与打开原文，不能演示空空间接收第一条内容或朋友如何加入。完成展示页不等于确定了新增、改错和共同使用过程。

以已有金华潜水分享为例，施工前需能连续演示：空空间 → 收下分享 → 相册与分类出现新内容 → 更正信息 → 朋友查看 / 加入 → 之后查找并打开。各处显示应该使用一致的演示数据。

## 候选与当前建议

- 继续只精修动态首页：保留美感，但后续实现仍需临时决定输入、空间和异常路径。
- 同时建设真实后端和所有平台接入：超出当前“施工前前端 Mock”的评审目的。
- **当前选择：在已有视觉和 R1 基线上，补齐可交互的主要流程及必要状态，再作为施工依据。** 用户随后明确要求保留现有产品基调进行调整；下表的 M1–M6 已在本轮本机实现，发布与用户验收分别记录。

## 本轮补齐的最小范围

| 项目 | Mock 需要展示的具体体验 | 验收证据 | 关联 |
| --- | --- | --- | --- |
| M1 · 第一次使用 | 从空空间开始，一人能收下第一条；示例内容与自己新增的演示记录能区分 | 不需要先邀请两人；没有数据时仍能看懂下一步 | ADR-0010 |
| M2 · 收下一条分享 | 明确入口、粘贴 / 接收分享、保存反馈；成功后封面轻轻进入相册并可查找 | 同一条新增记录可在相册、对应分组和搜索中找到；不靠固定跳转假装新增成功 | ADR-0009 |
| M3 · 查看与改错 | 在内容背面或详情层看完整标题和出处；按规则更正地点 / 类型、移除与撤销 | 更正后分类、结果和相关数量一起变化；外跳仍指向该内容；删除范围清楚 | ADR-0002、ADR-0004、ADR-0009 |
| M4 · 邀请朋友 | 发起人发出邀请、朋友看到邀请说明、查看 / 加入后的状态；显示谁可看、谁可操作 | 邀请流程能走完；只读与成员操作有可见区别；成员带来的内容进入同一池 | ADR-0010 |
| M5 · 有线索地回顾 | 封面附近显示实际已有的日期 / 分享人，能展开有依据的相关内容 | 不捏造分享时间或共同喜好；修改内容后线索与数量也保持一致 | ADR-0013 |
| M6 · 完整状态与手机操作 | 在上述流程中覆盖空内容、保存中、信息不全、失败重试、重复输入、无结果及操作撤销；检查键盘与底部按钮 | 失败时知道保留了什么、还能做什么；手机键盘出现后关键动作仍可达 | 跨上述议题 |

“收下一条”优先推进：它决定新内容如何进入所有现有视图。信息更正与新旧数据联动随后衔接，邀请和有线索的回顾沿同一份数据继续演示。

## 首次提案时的状态问题（保留讨论依据）

以下为建档时的候选；本轮已确定的去重、存储和角色演示选择分别记入 ADR-0015、ADR-0016，生产方案未因演示实现而确定。

- 没有封面或地点未确认：允许记录已取得的链接等信息，不能把字段齐全作为保存前提。
- 无法提取内容与无法保存：前者可保留链接待补，后者保留输入并允许重试，提示不能混用。
- 同一个链接再次加入：显示已有记录并提供查看路径是候选方案；是否追加一次分享事件、如何合并不同 URL 尚未确定。
- 原文这次打不开：已有标题与来源继续保留，仍允许再试；复制原链接 / 标题可作为补齐候选，不凭浏览器外跳结果自动判定作品已删除。
- 共同内容的修改与移除：施工前明确谁有权限及影响范围。可先考虑成员维护自己带入的内容，但尚未决定最终权限模型。
- 邀请：先明确展示范围与加入后的权限；是否同时有独立私人空间、多个共同空间、免登录预览，不能由“一人先用”自动推导。

这些具体规则产生结论时继续记入对应 ADR；若改变已经接受的决策则新建 ADR 并链接替代关系。

## 前端模拟与真实能力的界限

- 可以使用统一的本地演示数据，模拟新增、编辑、查找、移除、撤销和角色变化；演示应提供可重复进入和恢复初始样例的方式。
- 保存失败、提取不全、邀请加入等场景通过明确的演示控制展示；用户能够识别哪些是模拟状态。
- 网页可展示 iPhone 系统分享入口的示意与承接页；真正的系统分享扩展、平台解析、真实邀请访问控制和跨设备同步不能被标为完成。
- 若使用浏览器本地保存，注明仅该设备 / 浏览器有效；不能把刷新后保留演示记录称为云同步。
- 不为了显得完整而新增聊天、行程、打卡、公开推荐流或复杂设置中心；这些不属于本轮四个方向必需的流程。

## 施工前的完成标准

1. 体验者无需口头讲解，能从空空间走完收下一条、确认记录、找到并打开这条内容。
2. 修改或移除后，数量、分组、查找结果、原文栏和相关提示同步，不出现相互矛盾的视图。
3. 能走完邀请方与加入方的演示，理解内容可见范围。
4. 信息缺失或失败时有继续路径，已输入内容不会无说明地消失。
5. 每个主按钮的结果、返回状态及模拟边界有记录；手机窄屏、键盘、滚动和减少动态路径可验收。

这些是 Mock 交付条件。下方检查只证明列出的本机流程；无需口头讲解的上手能力、真实用户长期使用与真实平台接入仍按 R2–R6 独立验证。
