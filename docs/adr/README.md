## 什么讨论应留 ADR

下列内容每个核心点单独留档：需求 / 范围取舍、目标人群、核心交互、原文及内容处理、数据真实性、导入 / 同步 / 隐私边界、技术选型、收费 / 发布与关键验证方法。

同一核心点的进一步讨论更新原 ADR 的“讨论进展 / 未决问题”；产生新的独立问题就新增。纯错别字修正、没有行为变化的样式整理、一般状态查询，不必为了数量新建 ADR；发生交付时记入对应路线项即可。

## 状态语义

| 状态 | 何时使用 |
| --- | --- |
| 提案 | 已讨论或建议，但未确定采用；允许记录多个候选、反对意见和未决问题 |
| 已接受 | 用户明确确认，或已有执行授权且实现中作出了必要选择；写明依据，不能因建议出自助手就采用 |
| 已拒绝 | 明确决定不采用；保留理由与重开条件 |
| 已取代 | 整项决策被另一 ADR 替换；填写新 ADR 链接；仅参数被替代时保留主体已接受，并标明替代范围 |
| 已废止 | 已采用的方向停止生效；说明停止原因 |

每篇还要独立写实施状态：未实现、部分实现、已实现未发布、已上线，以及验证状态。**“已接受”不能当作“已上线”，“能演示”不能当作“有市场”。**

## 每次维护的动作

1. 讨论前读路线图及相关 ADR，找出当前结论与未决问题。
2. 讨论结束时，用模板记录具体问题、证据、候选、当前选择、取舍、未决问题与下次验证方式；未拍板也记为提案。
3. 检查是否改变旧决策。若改变，创建新编号，在两边写清“替代什么 / 保留什么”，保留原始理由。
4. 更新本索引与 Roadmap 的相关条目。没有新增实现时不改成已完成。
5. 实现或发布后补充提交、检查结果和发布证据；历史检查明确为历史记录。

使用四位递增编号，下一篇为 `0014-short-topic.md`，编号不复用。写中文正文，文件名使用简短英文。记录最少必要的用户原话或摘要，不在文档重复个人聊天明细、分享令牌和封面原始数据。

这些文档随仓库保存和版本化。维护发生在后续实际讨论 / 交付时，不代表已经创建后台自动监听或定时任务。
