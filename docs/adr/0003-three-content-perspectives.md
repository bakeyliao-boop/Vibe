# ADR-0003：用地点、类型、分享人查看同一内容池

## 问题与依据

用户要求地点、类型、分享人三个展示层，同时强调三人的同类内容可以放在一起。用户曾反馈展示缺乏快速上手能力，也不希望层层点击才能碰到内容。

## 候选与决策

- 三人各自独立内容线：不符合共同关联需求。
- 为每个视角设计一套特殊手势：增加学习和导航成本。
- **采用：顶部显式的地点 / 类型 / 分享人按钮，当前视角内可点组名或横滑；点封面选资源。** 三个视角共用数据和原文托盘。

用户明确提出三层与易上手要求；原型实施了这套操作结构。

## 结果与取舍

- 用户已选中“达那也潜水”后切到类型，应进入有依据的“动手体验”；切到分享人应进入其记录的贡献者分组。
- 当前使用 `primaryTypeById` 指定样例的主类型，不能称为系统理解了任意新内容。
- 选中内容跨三个视角不丢失，托盘保持指向同一原文；不同组卡片数量会改变尺寸和位置，**当前不是跨视角绝对坐标完全固定**。
- 在同一视角手动选择不包含已选内容的另一组时，当前实现清空选择，托盘跟随该组内容。这与切换三个视角是不同操作。
- 当前的“地点线索 / 逛看现场 / 单体对象”等类型是样例用语；发布前是否换成美食、游玩、攻略等用户熟悉的名称，仍待验证。

## 如何验证

让首次使用者完成“选中潜水 → 查看类型 → 查看谁分享 → 打开原文”，观察是否需要解释、是否丢失上下文。来源不明的内容也必须可操作，不补假身份。
