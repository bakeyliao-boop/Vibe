# ADR-0001：聚焦朋友分享内容的共同回溯

- 决策状态：已接受
- 实施状态：方向已落实到 Mock；真实收藏与共同使用未实现
- 验证状态：有真实需求案例；尚无产品使用验证
- 建档日期：2026-09-12（历史回填）
- 决策日期：未记录；不晚于 2026-08-12 首次原型提交
- 类型：产品范围
- 路线关联：[历史路线与当前阶段](../../ROADMAP.md)

## 问题与依据

早期同时探索朋友私人 / 共享空间和食物临期提醒。用户经常买大量零食，食品分散存放；逐件登记成本高，小票名称或普通照片不足以可靠判断产品及到期时间。讨论未找到用户接受的低成本记录方案，用户明确要求放弃食物 idea，转回朋友产品。

随后出现更明确的场景：记得曾分享过杭州萧山区某夜市，只剩大致位置和内容印象，跨平台、群聊与私聊翻找仍未找到，最终未去。用户要求把共同分享内容串起来，且反复强调“分享”不必意味着真的想去。

## 候选与决策

- 食品临期助手：存在明确问题，但本轮没有解决可靠录入与收益成本匹配，已放弃。
- 包含原创上传、共享相册等的泛朋友空间：保留为早期探索背景，不作为当前完整实现范围。
- **采用：围绕朋友分享内容的汇总、关联、浏览和回查。** 当前先用链接、封面与标题做可体验原型。

食物方向的退出是用户明确要求；共同分享回溯方向由之后连续需求与原型迭代确认。

## 结果与边界

地点、美食、攻略等可以共同保存，不按每个人各建一条独立线。允许暂时没有明确用途的分享；不能强制用户表达喜欢、想去或共同计划。

剧情、3D 网络和历史地层曾用于探索展示，但当前没有实施这些完整能力；不能从有限封面生成并宣称存在的共同经历。原始照片、实况照片和视频上传仍未落地。

## 如何验证 / 何时重看

用真实的小组旧分享测试“能否比原方法更容易找回”。若仅发起人有持续使用，需重新讨论共同使用是否是必要范围；若重新考虑食品，另建 ADR，不把已放弃方向悄悄加回。
