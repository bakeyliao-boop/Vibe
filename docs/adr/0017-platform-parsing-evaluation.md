## 具体问题与来源边界

侧对话用户将首版范围收敛为小红书和抖音，希望保存后就有可辨认、可找回的信息，尽量减少补标题、找封面与更正地点。用户询问 LLM 是否能理解链接，并要求参考已有产品怎样接通。

本档案依据转交摘要。临时对话的逐轮读取接口不支持回读，本轮未重新查看厂商网页或重跑样本请求。因此以下明确区分“厂商公开说明（转交）”“侧对话实测报告”“用户反馈”和“待验证提案”，不把它们合并成一项已经成功的 Vibe 能力。

原始测试链接及作品 ID 留在本机 `.local/parser-samples-2026-09-12.json`，由 `.gitignore` 排除，不提交到公共仓库；公开文档只保留 D1–D3 的匿名测试概要。该清单不包含令牌、密钥或登录凭据。

## 侧对话样本检查报告

| 样本 | 用户提供的内容线索 | 侧对话实际取得 | 尚未取得 |
| --- | --- | --- | --- |
| D1 | 给朋友做九宫格便当 | 短链可展开，并得到作品 ID | 经作品页核验的原题、实际封面及完整文案 |
| D2 | 江西、咖啡与种田 | 短链可展开，并得到作品 ID | 经作品页核验的原题、实际封面、具体城市 / 店名 / 地址 |
| D3 | 反向旅居，与鹤岗作比较 | 短链可展开，并得到作品 ID | 经作品页核验的原题、实际封面、真实旅居目的地 |

- 普通 HTTP 跟随跳转得到脚本页面，未提取原题或原封面。
- 使用 iPhone Safari User-Agent 请求时，三个移动页面均显示“抱歉出错了，请尝试在抖音内观看”；网页标题是通用平台标题，图片是错误提示图标。三条均没有取得有效的作品元数据。
- 正常浏览器自动化连接超时，侧对话没有成功检查渲染后的作品页。
- 用户截图中的标签显示了便当作品标题，用户报告“能播放视频，但是马上跳登陆验证”。是否可关闭、是否强制登录，未确认；这不等同于解析器取得了原文。
- 分享串中的开头数字或日期样式片段未当作评分或发布日期；标题与作者线索来自用户提供的分享文案，不冒充已核验的作品字段。
- 没有取得登录凭据、绕过验证、下载完整视频或向第三方解析器传送这批样本。

这些结果只说明本批样本在特定请求环境下未获得有效作品信息；不能推导整个抖音无法接入，也不能计算为成熟专用解析产品的失败率。

## 候选路线与当前提案

1. 通用网页读取：保留为一条候选路径；本次样本说明仅展开链接和获得 HTML 不足以完成保存目标。
2. 平台专用解析：分别评估小红书与抖音的适配路线，可比较自有适配与供应商服务；目前没有选定实现。
3. 用户浏览器辅助：可参考现有登录浏览环境的采集方式，需另评估手机入口、登录负担和维护成本。

建议评估的流程为：**完整分享文案 → 平台专用解析 → 作品信息有效性检查 → 保存原题 / 封面 / 配文及原文入口 → LLM 辅助理解主题、类型和地点关系。**

原始分享文案应先保留，解析结果通过校验后再补充。错误页、登录页、通用标题和占位图不能覆盖原始输入；HTTP 成功不作为作品解析成功的判据。

LLM 的候选职责是解释已取得的资料，不能凭 URL 补造原封面或实际未取得的正文。地名需要区分角色：D3 的“鹤岗”是比较对象，不能直接归为目的地；D2 只能确认文字提及江西和咖啡，不能补出城市或店铺。

初期可参考 Cubox 的“封面 + 配文 + 原文播放入口”结果范围；完整视频归档和视频内容总结不作为这次接入评估的必要成功条件。真实保存的目标是尽量减少手工补资料，本机 Mock 的手动补充只是已存在的补救路径。

## 下一项评估与验收证据

复用 D1–D3 和已有小红书样本，为每一条候选路线记录：

- 输入的原始分享文本、平台和样本编号，以及检查日期 / 环境。
- 是否命中同一作品，标题是否为原题，封面是否对应作品，文字是否完整或截断；未拿到与拿错分开记。
- 遇到登录 / 错误页时是否识别失败，是否保住原始输入，能否重试；不能把错误页包装成内容卡片。
- 用户是否需要登录、跳转、手动补资料，以及需要多少步骤。
- 每次保存延迟、实际调用成本、服务限制与维护负担；没有测试或报价时写“未测”，不补预算数字。

比较结果出来后再确定技术方案、供应商与 LLM 用法。现有研究没有授权购买服务或向任何具体第三方传送样本；实际评估应确认届时已有授权和测试范围。
